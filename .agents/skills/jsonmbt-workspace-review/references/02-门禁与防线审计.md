## 1 · 阶段 1 的门禁怎么跑

- 命令全表在 `06`。每个门禁记它**自报的稳定单行**当基线（`Total tests: N, passed: N` / warning 数 / CLI 抽验的 rc）。
- `moon check` warning 总数 = 免费回归信号：审"修复批"改前 / 改后比总数，增量落到 `文件:行`。
- **测试计数真值 = 测试运行结果**（AGENTS 纪律 3：单点归一）。文档（README / PLAN / 提交信息）里的计数引用与本轮实测对账——不符即"文档漂移"发现，处置是**改文档引用**，禁改测试预期。
- 样本锚连跑：`probe/samples/` 现两层（期望 `.json.mbt` → 黄金降级产物；importer 输入层随 P1.5 落地补齐为三层）。只验一层 = 假绿（改了降级器没重锚黄金产物的漂移抓不住）。

## 2 · 审「新加的锚」（moon test 语义锚）

**有牙判定**：对锚声称覆盖的每个实现点做突变注入（改坏）+ 对照注入（同时改坏 1–2 个已知有锚的点）——只有前者全绿而后者红，才叫"**这一点**无锚"。

专项核对：

1. **负样本锚覆盖度**：J 码表（`src/diag.mbt`）每个码至少一个负样本锚（PLAN §6 J 系行纪律）。查法：J 码清单 vs 测试里的负样本逐码对账。
2. **层同步**：新增样本是否层齐备（现状两层：期望 `.json.mbt` / 黄金降级产物；P1.5 后三层加 importer 输入）。
3. **样本判别力**：按 `01` §1 矩阵查"锚只取一种形状"（数字全族 / 转义全族 / 键名全族各至少一个判别样本）。
4. **D 系对应**：PLAN §8 每条 ✅ 终案裁定至少落一个锚（R10 文档/实现比纪律）——查法：D-1~D-11 逐条找锚，找不到 = 规范降级草稿，报 P2。
5. **锚别把工具链漂移行为锚死**：行为锚（非类型层）可能把某版工具链的行为固定成预期——moon 升级后跑行为矩阵（R1 对冲），红 = 先判"锚错"还是"真回归"。

## 3 · 审「新加的闸 / 防线」——三层，缺一层就不算验过

1. **会红且双向**：注入篡改（改坏实现 / 改坏期望）→ 期望红 → 还原复绿。
2. **它声称堵住的盲区真堵住了吗**：把原缺陷场景**原样复现**，看闸是否红。真值来自缓存制品的闸 = **复述不是对账**（须强制新鲜度）。
   - **常数族判别力**：闸若声称按某常数族渲染/判定（行宽、深度预算、阈值），样本必须落在**常数临界两侧各一**——样本全落安全区 = 闸只对样本形态负责、不对常数负责。查法：把常数改坏注入，全绿 = 零判别力坐实。
   - **SKIP 路径进自我报告**：门禁因环境缺席（工具不在 PATH 等）SKIP 时，汇总必须带 skipped 计数——`total=N failed=0` 与真实全跑不可区分 = 防线自我报告失真。SKIP 路径在环境恒全的机器上从未被触发，要主动演练一次（去 PATH 跑）。
3. **接线**：本仓**当前无 CI** ⇒ 接线层结论只能是"未接线（本地手验流程）"，报告如实标注；提议接 CI = 仓库变更，提请用户拍板。
   - 层 2 Go 黑盒驱动（P1.5）落地后按 Vitro 同款三件审计：**exe 新鲜度门禁**（测前核 exe 构建时间 vs 源码 mtime；审"已提交的批"时 mtime 不够，要比 HEAD 短哈希）、**golden 逐字节管理**、**校验和计时纪律**（基准对照校验和逐位一致才计时）。

**D-8 ③ 专项（check = build dry-run）**：两套校验路径必漂移是明文警告。审计法：对校验逻辑单点注入（如放宽 J3004 判定），分别跑 `check` 与 `build`——只有一侧变红 ⇒ 违反"同一条校验路径"。

**CLI 进程契约（D-10）抽验**：rc 五值逐值验（0/1/4 现用，2/3 保留）；stderr 机器可读前缀格式（`jsonmbt: error [Jxxxx] path:line:col`）；stdin `-` 契约；**原子写**（校验失败零产物、不覆盖已存在 `.json`、无 tmp 残留）；**确定性**（两次 build 逐字节 diff）。

## 4 · 审人写的分析型 / 判定型脚本——六问清单

1. **默认参数匹配用途吗？** 原样跑一遍，看输出结论与用途是否一致（参数写死在代码里的窗口期/阈值尤其要核"它自称要量的那段是否为空"）。
2. **同一份证据是同一套参数产出的吗？** 参数写死 ⇒ 两份输出可能互相矛盾且不可复现。
3. **能否会红 + 灵敏度多少？** 造最小 fixture 验正检；再造低于阈值的样本验**漏检**——漏检要明写成结论。
4. **静默失败面**：不存在的根 / 空目录 / 读不到的文件，是 fail loud 还是打印"0 条"？（打印"0 条"且 exit 0 = 与"真无问题"不可区分。）
5. **归一化口径的假阳 / 假阴**：只跳整行注释不剥行尾；拼接跨注释块；不区分生产码与测试文件；重叠窗口不合并。
6. **文档 / 字段与实现是否一致**：头注声称的机制 vs 实际机制；死字段。写进报告时给相对路径留证。

## 5 · 数字审计：先反证口径，别改数字

- 见红先反证**假阳性**：先对齐口径（同一命令不同口径可能都对），再判对错。
- 本仓**无 facts 机判** ⇒ 文档数字全靠手工对账，更要标注证据等级（`已实测` / `仅读码` / `未覆盖`）。
- **计数真值单点归一**：测试数等计数真值入测试运行结果，文档只引用——发现两处文档各自维护数字 = 结构性漂移面，报 P3 建议归一。
