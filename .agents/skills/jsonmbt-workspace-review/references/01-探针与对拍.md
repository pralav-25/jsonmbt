# 探针与对拍

> 阶段 3 / 阶段 4 的具体做法。**只在真要做探针时读。**

## 0 · 通用纪律

- **探针留证**：复杂 / 难以重建的探针放 `tmp/review_YYYYMMDD/`（已 gitignore），报告里给**相对路径**；一次性小探针**用完即删**，`git status -uall` 确认零残留。
- **探针 `.mbt` 禁放仓库根**：根目录 `.mbt` 与主包同包全编译（AGENTS 环境注意）——临时探针 test 块只进 `src/*_test.mbt` 且用完即删，独立工程放 `tmp/` 下。
- **先证会红**：探针本身也要证明它有能力报错（喂一个已知坏的输入，看它红不红），否则"探针全绿"无意义。
- 跑完删树内副本后**复跑 `moon test` 确认计数回落**（探针 test 块会让总数 +1）。
- **真机端到端优先于白盒自证**：CLI 能跑到的面（rc / stderr / 产物字节 / 原子写）直接跑 exe，别只靠白盒锚。

## 1 · 输入形状探针矩阵（3a 主战场）

语料对每个构造通常只锚**一种形状**，换形状就出盲区。高发形状（全部可用 CLI 端到端探，模板见 `06`）：

| 形状族 | 必测样本 | 为什么容易漏 |
|---|---|---|
| 数字形态 | `1` / `1.0` / `1e2`（**解析错**）/ `1.0e2`（合法）/ `-0.0` / `2147483647` / `2147483648` / `9223372036854775807` / 超 Int64 | MoonBit Int 是 32 位；`1e2` 纯整数尾数接指数是解析错——从 JSON 侧外推全翻车 |
| 字符串转义 | `\'` `\"` `\\` `\n` `\r` `\t` `\b` `\f` `\0` `\x41` `\u{1F600}`（1–6 位）/ 裸控制字符 / 独代理对 | 解码器（`src/unescape.mbt`）与输出侧统一转义（`\u00XX`）是两段代码，各自漏一半 |
| 容器形状 | 空数组 / 空对象 / 深嵌套（深度预算临界 ±1）/ 数组异构元素 | 空容器走 D-1 阻断诊断，同形复用启发是另一条路径 |
| 键名形态 | snake_case / 驼峰 / 中文键 / 保留字 / 连字符 → Map 逃生门 / 同对象混合 | Map 逃生门是"同对象整体降级"，单键注入不红 |
| 文档基数（D-7） | 单 `pub let` / 多 `pub let` / 内部 `let` / stem 与绑定名不符 / 缺 `pub` | 每条都是独立 J 码（J2001–J2007） |
| stdin / IO | `-` 单输入 / `-` 混文件输入 / 无尾换行 / CRLF / 空文件 / 非 UTF-8 字节 | stdin 形态是独立通道，文件锚盖不到 |

判别力自检：对每个样本问"**它能反证哪个候选实现**"——`1` vs `1.0` 对"N 值语义"零判别力（值层不可分），对"输出侧 raw 直传"才有判别力。

## 2 · 白盒探针（moon test 内）

`assert_eq` 失败**只报 FAILED 行、不含实际值** ⇒ 用 `fail(s)` dump：

```moonbit
test "tmp_dump_xxx" {
  let s = <被审函数在边界输入上的结果拼串>
  fail(s)
}
```

- 临时探针写进 `src/*_test.mbt`（本仓单包），**跑完即删**并复跑确认计数回落。
- 抓 dump：`moon test 2>&1 | sed -n '/FAILED:/,$p' | sed '1s/.*FAILED: //'`。
- 独立探针工程（要单独 `moon.pkg` / 依赖面时）：`tmp/review_YYYYMMDD/<name>/{moon.mod, src/moon.pkg}`——`moon.pkg` 不可省（缺它 = 静默 EXIT=0 零产物，陷阱 #36 同族）；native 侧记得 `MOON_CC=clang`。

## 3 · 突变注入循环（阶段 4 的执行法）

```
备份 → replace(old,new,1) → sleep ≥1.5s → moon test -p vitro/jsonmbt/src → 记录 failed
→ 还原 → 复跑确认回落（finally 里再还原一次，防中断留脏）
```

- **增量编译漏检**：连续快速改写同一文件可能复用旧产物 ⇒ 注入与测试之间 `sleep ≥1.5s`；首轮结果不可信时重做。
- **无锚判定必须带对照**：同时改坏 1–2 个已知有锚的点。否则只能说"整套没牙"，而非"唯此一条无覆盖"。
- **"改坏不红"分两种性质**：① 真锚盲区（要报）；② 等价分支（兜底路径殊途同归）⇒ 读码判定不硬报。**判据：能否找到一条区分两条路径的输入形状**。
- **反向突变（审修复批）**：把修复还原成缺陷版，期望对应用例红；记录红的用例名。`failed == 0` ⇒ 修复写了但锚没牙。**先读提交自称的锚在哪**（提交信息"锚/闸/防线"字样），再去那道闸上注入。
- **修复尝试注入（双向第二证力）**：把**合规实现**注入看测试是否仍绿——绿 = 锚聋实锤，与「改坏看是否红」互为反向。专治「锚只锚了实现现状」的形态：pre-pass 闭合判定、上下文参数补传、防御分支（守卫从无到有）皆此法——这类改动"做对了"锚也无反应，单向改坏探不出。
- 可注入点样本（jsonmbt 高发）：J 码分派臂换码号 / 降级器 emitter 某臂改直拼 / 深度预算 `- 1` 改 `+ 1` / 原子写去掉 rename / 转义表删一条 / stem 校验放宽。

## 4 · 数字 / 浮点面的对拍口径

- **本仓浮点机制（判据以此为准）**：降级输出 = `Json::Number` repr **源文本直传**（`src/l0.mbt` num_json 把 repr 钉到归一文本；超范围大数走 out-of-range fallback 保源文本），格式化面在本仓不出现。`double_to_json_text` 是 Vitro `moonbit/ast` 私有函数——**本仓不可 import、grep 必零命中**，照 PLAN 旧表述执行会误报。
- **裸 `Double::to_string` 三分歧**（整值 `1.0 → "1"`、负零 `-0.0 → "0"`、中段指数记法不同）仍是知识：它解释 N 层 canon 为何只在 repr 缺失时才 `to_string` 兜底（`src/normalize.mbt`，ryu 短表示归一），以及未来若引入格式化面必须对齐 ryu-pretty 语义。
- **两维度分立**（D-11）：N 值语义层 `1 ≡ 1.0`（core/json repr 常规数字不可分）；输出保真层 `1 ≠ 1.0` 保留（repr 直传）。审往返锚时先问"这句等价说的是哪一层"。
- **repr 特性**：`Json::Number` 的 repr 仅对超 Double 范围大数保源文本（out-of-range fallback）——别把"repr 有值"当"常规数字可分"的证据。
- **整数边界**：Int 32 位（`2147483647` / `2147483648` 是分界样本）；Int64 位用字段位裸字面量（无 `L` 后缀）构造；超 Int64 = 诚实拒绝面。

## 5 · 往返对拍（D-11 执行法）

判据：`N(build(import(J))) == N(J)`。步骤：

1. 取输入 JSON `J`（含边界形态，见 §1）。
2. `jsonmbt import J` → `.json.mbt`（P1.5 后）；`jsonmbt build` → 产物。
3. 两侧各过**规范化器 N**（数值十进制规范形 / 字符串按码点 / 键序源序）再比——**禁逐字节比**。
4. 落在登记的不可逐字节面（整数尾数指数 / 超 Int64 / 超 17 位有效数字 / **重复键=拒绝**）的样本：核"是否按登记口径拒绝"，而不是核等价。

## 6 · moon 工具链真值探针（3b，探针先行）

任何"moon 会怎么解析 / 怎么定型 / `Json` repr 长什么样"的主张，**写最小探针程序拿一手真值**，禁从文档、记忆或 JS 侧外推（历史实证：Int 位宽、`1e2` 解析错、`Constant::String` raw 未解码、`Constant::Int64` raw 不含 L——全是探针修正的）。

- 探针结论属**规范事实**：要进 PLAN 的（新陷阱 / 新边界），提请用户登记；agent 不自行改 PLAN。
- 与 `docs/MOONBIT_PITFALLS.md` 对账：探到的坑若已在陷阱快照里（编号对齐 Vitro），引用原号；不在 ⇒ 登记进本 skill `04`，回灌陷阱文档由用户拍板。
- **低成本真值路径**：`examples/` 自带 `moon.pkg` 即在编译面——临时样本丢进去跑 `moon check` 即得 moon 真值（parser 收不收、类型错不错），用完即删，省一套独立探针工程。

## 7 · fmt 不动点对拍（生成器行宽/折行面）

- **fmt 真值定界法**：判「某行宽会不会被 moon fmt 改写」用 solo 包 + **手工规范形**逐宽度逐字节扫描——用生成器产物反推会因 block 化掩盖真值界（超宽形态早被折进 block 区，探不到顶层数组的临界）。临界形态（恰好等于/超一行宽）各留一版。
- **单文件逐档协议（多文件批扫不可信）**：宽度矩阵**一次一个新文件名**（写 → sleep ≥2s → fmt → 判该行是否原样存活）——多文件同批扫描会撞 fmt 增量缓存：同档两轮结果翻转（82 宽一轮存活一轮展开），部分文件实际未被处理而误判存活。同档结论自相矛盾 = 缓存假存活的签名，须换单文件协议重采。
- **手工规范形要先验自己的规范性**：fmt 会给「缺尾逗号的单行 record」补 `, }`——用非规范形扫界会把「补逗号改写」误判为「宽度展开」。先跑一档 fmt 看产物形态，确认输入即规范形再扫。
- **shadow fmt 假绿陷阱**：影子包缺 `moon.pkg`（或格式坏）时 `moon fmt` **静默不跑**、前后 diff 全相等假 stable。哨兵先证红不可省：先放一个已知会被 fmt 改写的文件，确认影子包真的会改它，才开始收集 stable 证据。
- **折形漂移核对**：对生成器产出的每种折行形态（嵌套折、容器折、函数式包裹如 `Some(`）与 fmt 后形态 diff——生成器自认的折形 ≠ fmt 规范形即漂移（fmt 对短值还会把两种折形全收敛单行，双向都要探）。构造器包裹（`Some(`/变体名）的规范形 = **包裹符与值首行同行**、闭符贴块尾，不是「包裹符独占一行」。
