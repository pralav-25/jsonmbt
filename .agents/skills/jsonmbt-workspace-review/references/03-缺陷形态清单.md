# 缺陷形态清单

> **开审前扫一遍。** 本表按"形态"聚类。起步版（2026-10-07 建）：条目取自 PLAN 已实证的坑与高危面，**尚未在本仓审阅中批量验证**——每条都是"查法"，不是"已坐实的缺陷"。
>
> 用法：拿到一批代码，按本表逐类过一遍（每类给"判据 / 查法"），比从头读一遍命中率高得多。
> **新形态追加到本表**（规则见 [`05-演化机制.md`](05-演化机制.md)）。
>
> **实例写法四条**（承 Vitro，防止单点腐化）：
> 1. **禁写一次性测量值**：测试数、`PASS n / FAIL m`、批次号、文件数——随代码演进而过期，本表只增不改，过期数字没有机制修正。
> 2. **允许写"形状"而非"真值"**：对比关系、临界样本（`2147483647` / `2147483648`）、触发条件属于判据本身，可留。
> 3. 日期只保留"形态最早可考"的场合，写成 `（Y-M 立）`。
> 4. **实例优先给"可复现判据"**（一条命令 / 一段注入写法 / 一个 `文件:行`），其次才是"当时观察到什么"。

## A · 锚的问题（测试写了但没有牙）

> **共同查法**：突变注入（改坏）+ 对照注入（改坏已知有锚的点）。只有前者全绿而后者红，才叫"这一点无锚"。

### A1 · 负样本锚覆盖不全（J 码有定义、无锚）

- **判据**：`src/diag.mbt` 的 J 码在测试里找不到至少一个负样本（PLAN §6 纪律：每码至少一负样本锚）。**CLI 层码（J0001 用法 / J0002 IO）天然在 `src` 单测覆盖面外，锚位在进程契约层（当前手验）——对账按层分桶，别对 src 单测报 CLI 码缺锚**。
- **查法**：J 码清单与负样本锚逐码对账（分桶：库面码 vs CLI 码）；对缺锚的码，注入"该发此码的错实现"看红不红。
- **处方**：逐码补负样本；J 码分派臂的突变注入是最低成本的体检。
- **同族面：码级有锚、臂级漏锚**。J 码分派臂族须做**同构突变注入**——同码可能只锚了一个臂，其余臂改错码全绿（对照法：同码另一臂的锚红，证框架有牙，唯此臂漏）。「fail loud 最后一道兜底臂」必须有专属判别输入（最便宜的是白名单外最小构造，如 Tuple）——头注释自称的教训（"不设 null 兜底"）只在注释没进锚 = 教训未锚定。

### A2 · 锚只取单一数字 / 转义形状

- **判据**：降级器 / 往返锚的样本里，数字只有常规整数、转义只有 `\n` 一类常规项。
- **查法**：按 `01` §1 矩阵列形状清单对账——`1e2` / 负零 / `2147483648` / `\0` / `\xHH` / 独代理对各至少一个判别样本。
- **实例（判据来源）**：`1e2` 是解析错而 `1.0e2` 合法；负零走 ryu-pretty 有独立形态——只锚 `1` / `2.5` 的锚对这些面零判别力。
- **同族面：负样本锚矩阵须含「清洗后变形」输入域**。sanitize/归一函数的锚只锚「原文形态」（如小写保留字 stem），漏「清洗后才产生坏形态」的交叉域（大写开头保留字经小写化撞回保留字 = 该输入域全链死锁）——对每个清洗函数，把**它的输出域**当输入域再对账一轮。

### A3 · 锚把工具链漂移行为锚死（锚错 > 锚漏）

- **判据**：行为锚（非类型层断言）的期望值来自"某版工具链的实测"，而非规范判据（RFC 8259 / D 系）。
- **查法**：moon 工具链升级后，先判红的是"锚过期"还是"真回归"——跑最小行为矩阵（R1 对冲流程），别按锚的旧预期改实现。

### A4 · 生成器源文本直传 vs 目标语言字面量文法（跨语言转写）

- **判据**：任何「把 A 语言文本原样写进 B 语言字面量」的通道，A 的文法 ⊄ B 的文法即产非法产物——**用产物回吃自家校验器逐条证**（生成 → check 必须 rc 0；红即 P1）。首轮实锤：jsonmbt P1-1（JSON 合法 `1e2` 写不成 MoonBit 字面量——纯整数尾数须补 `.0`）。
- **查法**：对每个直传通道枚举 A 文法特征（进制/指数/转义/边界值），逐形态生成后回吃；生成器侧应有 `ensure_*_syntax` 改写函数 + 端到端自校验保险丝，缺一即缺陷。

### A5 · 推断中间态经容器包装逃逸（has-X 只查最外层）

- **判据**：中间态占位（如 `JTEmpty`/`?`）的消除判定若只 match 最外层，穿 `Option`/嵌套容器即泄漏非法类型（`Array[?]?`、`Array[Array[?]]`）。首轮实锤：jsonmbt P1-3/4。
- **查法**：对每个中间态 grep 全部判定点，逐一问「穿透容器后还成立吗」；收尾应有全量断言（残留即 fail loud）——断言缺失本身即缺陷。

### A6 · 语料/样本锚无 runner 且不在编译面（摆设锚）

- **判据**：样本目录（golden/语料）无任何 runner 消费，且不含 `moon.pkg`（moon 根本不编译）——内容再对也不构成门禁；注入破坏后门禁无反应即坐实。首轮实锤：jsonmbt P2-2（probe/samples）。
- **查法**：`grep -r <样本目录>` 全仓找消费方；无消费方 = 摆设——要么挂进 test runner，要么挂进层 2 驱动（样本黄金逐字节），要么删。
- **同族面：锚中间层无再生闸（有 runner 只消费一半方向）**。样本锚被 runner 消费 ≠ 全方向有闸——runner 可能只把期望中间产物当**输入**喂下游，「输入 → 期望中间产物」方向零闸，漂移已实际发生（改了生成器没重锚中间层）也无闸红。查法：对每层锚问「这层内容被哪条闸**作为验证对象**消费」；跑再生方向对拍（`import(X.json)` vs 期望 `.json.mbt`）不一致即锚过期坐实。处方：再生闸 + **显式豁免清单**（人写模范本逐条带豁免理由——豁免清单即「人工审阅命名」的机判化承载）。

### A7 · 门禁脚本 rc 恒 0（防线无牙的进程级形态）

- **判据**：CI/门禁调用的脚本（smoke/check 脚本）断言失败只 `console.log`/`print`，无 `process.exit(非0)`/`throw`——rc 恒 0，门禁承诺（"红不上线"）不成立。跑绿 ≠ 有牙。
- **查法**：**注入坏断言跑 rc**（把断言目标改成必错值执行，rc 必须 ≠0）——只"跑一遍看输出"查不出本形态（本轮审阅五阶段跑了 smoke 却没抓到，注入阶段才坐实）。
- **处方**：末尾显式 exit 非 0；文件头口径与实际角色对齐（"一次性勘探勿入防线" vs CI 部署门自相矛盾也要修）。对照：Go driver 用 `os.Exit(1)` 才真判红。
- **同族面：门禁输入不可达 = 静默 0 条**。freshness/扫描类门禁读不到输入根时 err 被吞 = 零 stale = 通过——「检查不到」与「没有过期」同型。查法：把门禁挪到错误 cwd / 让输入根不可达跑，期望它 fail loud（正常环境下目录恒在，此路径从未被演练）。处方：入口先 stat 输入根，不存在即 error。另：门禁因环境缺席 SKIP 时，汇总行必须带 skipped 计数——`total=N failed=0` 与真实全跑不可区分 = 自我报告失真。

### A8 · 宽松 pre-pass 无闭合态判定（消解式转换吃掉非法输入）

- **判据**：字符层消解/归一化的 pre-pass（注释转空格类）对「未闭合结构」默认消费到 EOF，把非法输入消解成合法——与裁定「不收」清单冲突；其余「不收」形态全拒，唯独此项越界。
- **查法**：对每个 pre-pass 构造 **EOF 截断输入**（`/*x` / `"x` / `[1,`）逐个核默认行为 vs 裁定「收/不收」清单；「不收」清单**逐项**挂负样本锚并对账（有锚面也可能恰好漏其中一项——其余 8 项有锚第 9 项漏网的实证）。双向验证：注入**合规实现**（未闭合报错）看锚是否仍绿——绿 = 锚聋实锤。
- **处方**：pre-pass 返回闭合信号，未闭合 raise 指向起始位；随修补负样本锚（红→绿纪律）。

### A9 · 转义写/读两侧语义错位（形态锚抓不住，须往返值锚）

- **判据**：写侧 escape 与读侧 unescape 是两段代码——写侧格式错（如把码点十进制写进 hex 语义的 `\u{...}`）两侧语法都合法、值却静默改变；「产物 contains 形态 + 语法回吃」类锚全绿，错值照过。
- **查法**：控制字符/转义全族造**往返值锚**（import → build 比解码后的值，不是比形态）；单数字码点常巧合正确，**两位数控制字符**才有判别力；锚里已有的 `\u{...}` 类期望值逐个验进制——锚可能把错误形态锚死（A3 近亲，锚错 > 锚漏）。
- **处方**：写侧格式与读侧解析对齐单一事实来源；往返值锚覆盖两位数控制字符。

### A10 · 码元索引 `s[0]` 的空串可达性

- **判据**：`s[0]` 取首码元无空串守卫——标签/键名派生链入口若可达空串（RFC 8259 空键合法），panic 绕过 J 码通道与 rc 五值契约（进程崩溃级）。
- **查法**：全文件 grep `[0]` 码元索引逐点问「空串能到这吗」；同族对照——capitalize/sanitize 类派生函数常有守卫，漏的常是**新分支**（如同族臂不对称）。
- **处方**：入口统一守卫或空串即落备用路径（与同族输入同路，如空键走 Map 逃生门）；负样本锚补空键形态。

## B · 分叉与等价问题（实现面）

### B1 · MoonBit 语义从外推断（本仓第一高发）

- **判据**：实现或审阅结论含"应该是 / 按 JSON 的习惯"类推断——Int 位宽、字面量语法、String 语义、Map 序。
- **查法**：任何语义主张必须有探针真值背书（`01` §6）。历史实证：Int 是 32 位（外推 2⁵³ 被推翻）、`1e2` 解析错（外推"JSON 合法即合法"被推翻）、`String` 比较非字典序。
- **处方**：结论前先跑 `01` §6 探针；PLAN 已实证的直接引用，不重推。
- **同族面：跨仓判据移植未做本仓落地校验**。从别的仓（PLAN 引文 / 陷阱快照 / 他仓 skill）抄来的判据若含**具体函数名 / 包依赖**，先验证在本仓可解析（grep 全仓 + 对 `moon.pkg` 依赖面），否则照字面执行者会 grep 出误报、甚至去 import 不存在的包。实例：Vitro ast 的浮点格式化函数名被照抄进判据，本仓依赖面无此包、全仓零命中——本仓真值是 repr 源文本直传（`01` §4）。

### B2 · check 与 build 两套校验路径漂移（D-8 明文警告）

- **判据**：`check` 与 `build` 对同一输入判定不一致（一侧红一侧绿），或校验逻辑在两条路径里各有一份。
- **查法**：对校验逻辑单点注入后分别跑 `check` / `build`——只有一侧变红即命中；grep 校验函数被两条命令路径各自调用的证据。
- **处方**：check 必须复用 build 的同一条校验路径（dry-run）。

### B3 · 输出通道与 IO 面的形态漏审

- **判据**：审了"算得对不对"，没审"写出去对不对"——stderr 前缀格式、原子写、同名覆盖、CRLF / BOM / 无尾换行输入。
- **查法**：`02` §3 的 CLI 契约抽验逐项跑；原子写专验"失败零产物 + 不覆盖旧产物 + 无 tmp 残留"三态。
- **同族面：行尾归一消费点三连**。幂等闸（行尾归一比对）、fmt 影子比对、byte 类榜三处各自消费「行尾归一」——归一实现一处坏（如 replace 只换首处）则三处齐假红/掉榜；自家产物恒 LF、CRLF 只来自外部 checkout/编辑器 ⇒ 防线盲区**结构性存在**（锚全 LF 探不到）。查法：对三处各喂「同内容仅行尾差」样本对拍。

### B4 · 类型改写/查表分化的消费点漏覆盖

- **判据**：同一「原始形态 → 内部形态」改写（如 parse_type 产 JTStruct 裸名 → resolve_custom 查表分化）在多个消费点各自手工调用——漏一处 = 该路径上改写不生效（本轮：root_ty 与 struct 字段侧都 resolve，唯 enum payload 消费点漏 → `Named(X)` 合法输入误报 J3004）。
- **查法**：grep 改写函数的全部调用点，对照该类型流通的**全部**消费位（类型头/字段/payload/嵌套容器）；对可疑消费位构造「改写才会绿」的最小用例（嵌套引用形态最易漏——它需要改写后恰好命中另一张表）。
- **处方**：消费点补改写；锚补「改写才绿」用例（注入修复后测试仍全绿 = 锚聋的直接证据）。
- **同族面：上下文参数在同族递归臂的传递漏一处**。递归判定/合并函数的同族臂（数组臂/Map 臂/Option 臂）**并排列出**，数「几个透传了某上下文参数（如逃生门标记）、几个没传」——漏传臂的错误被外层聚合吞掉后报错码错桶、不点名根因。验证手法 = **补参注入**（反向突变）：给漏传臂补上参数后测试仍全绿 = 现状（漏传）无锚钉住。

## D · 闸 / 文档 / 流程问题

### D1 · 规范/实现比失步（R10）

- **判据**：D 系 ✅ 终案裁定找不到对应测试锚；或实现有 PLAN 没登记的行为。
- **查法**：D-1~D-11 逐条找锚（双向：规范有实现无 = 草稿；实现有规范无 = 偷跑）。**锚不是规范载体**：锚与实现常同批生成，锚测的是「实现做了什么」不是「PLAN 允不允许做」——行为有实现有锚、PLAN 正文无裁定 = 偷跑（对账必须到 PLAN 正文，锚注释自称的裁定名不算）。
- **处方**：缺口列清单提请用户裁决（补锚 or 登记规范）；agent 不自行改 PLAN。

### D2 · 文档数字漂移

- **判据**：文档里的测试数 / 计数与实测不符；或同一计数在两处文档各自维护。
- **查法**：本轮实测 vs 文档引用逐处对账；计数真值应单点归一（测试运行结果）。
- **加查**：同一文件/目录内两处描述同一数字（正文 vs 表格、README vs 代码注释、资产参数多处）互斥——以产物实测为权威，逐处对齐（首轮：assets/README x=162 vs x=174 vs banner.svg 实际 x=176）。
### D3 · 声称已对齐 / 已登记而实际未对齐

- **判据**：注释 / CHANGELOG / 提交信息写"已对齐 D-x""已登记"，但 PLAN 或锚里找不到对应物。
- **查法**：声称类结论反查——grep 注释与 PLAN 两边，两边都有才算登记。

### D4 · 模拟器与真实路径的参数初始化失真

- **判据**：工具内同语义两套路径（预演模拟 vs 真实执行）参数初始化不同源——模拟漏真实路径会考虑的输入（本轮：migrate 的 taken 从 `[]` 起始，真实 import 扫输出目录既有 .mbt）→ `--write` 产物与真实 import 不一致，自家的幂等闸 rc=2 自相矛盾。
- **查法**：找模拟器的每个输入参数，问「真实路径这个参数从哪来」；**自洽闸对拍**是最便宜的证红：模拟产物落盘 → 跑真实路径的校验闸（如 `import --check`），rc≠0 即失真坐实。
- **处方**：模拟起始值改为复用真实路径的扫描函数（per-directory 粒度对齐真实扫描基准）；防线补自洽闸用例。
