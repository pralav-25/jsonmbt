# 工具链与踩坑（审阅流程特有）

> **单点归一**：MoonBit 语言 / 工具链**确定性事实**的权威在 [`docs/MOONBIT_PITFALLS.md`](../../../../docs/MOONBIT_PITFALLS.md)（Vitro 快照 41 条 + jsonmbt 回灌 #42，编号对齐），本表**不重复**，撞到语言坑先查那边。
> 本表只登记**审阅流程本身**与 jsonmbt 环境特有的坑。写入规则见 [`05-演化机制.md`](05-演化机制.md)。
> AGENTS.md 纪律 8/9 的工具陷阱为本表上游，此处只展开审阅场景。

| # | 坑 | 表现 | 处置 |
|---|---|---|---|
| 1 | **native 构建默认 clang** | MSVC 撞 moon#2254 构建悬崖 | 一律 `MOON_CC=clang moon build --target native`（AGENTS 纪律 9），审阅里所有构建命令都带前缀 |
| 2 | **跨会话 `_build` 缓存毒化** | 并发会话改源后增量判定 up-to-date，产物仍是旧代码——"同源不同果"酷似语义 bug（陷阱 #41） | 跨会话接过工作区、消费产物做行为验证前，先清对应 `_build` 增量重建；"产物 mtime 新"不构成"含新代码"证据 |
| 3 | **管道吃掉真实退出码** | `cli check x.mbt \| tail; echo $?` 读到的是 `tail` 的退出码——实测现场：CLI 明明报 J0001，`rc=0` | 判 rc 一律裸命令跑（或 `PIPESTATUS`）；`| head` 还会 SIGPIPE 杀进程，判失败前 tail 全量（AGENTS 纪律 8） |
| 4 | **探针 `.mbt` 放根目录 = 污染主包编译面** | 根目录 `.mbt` 同包全编译——探针 test 块让 `moon test` 总数 +1、探针语法错拖垮整个包 | 探针进 `src/*_test.mbt` 用完即删（复跑确认计数回落），独立工程放 `tmp/` 下自建 `moon.mod` + `moon.pkg`（**须自带 `moon.mod` 才成嵌套 module 边界——只放 `moon.pkg` 会被上级仓吞进编译面，见 #12**） |
| 5 | **`moon.mod` + 块式 `moon.pkg` 是本仓格式** | 新工具链下 JSON 式配置解析失败（陷阱 #42） | 新建探针工程照抄本仓格式：`moon.mod` + 块式 `moon.pkg`，别写 `moon.mod.json` |
| 6 | **`supported_targets = "native"`** | `moon test -p cmd/jsonmbt` 不带 target 会撞 wasm 拒绝（cmd 包 native-only）——与选择器长短式无关（`-p src` 短式实测可用） | 单包跑 CLI 包加 `--target native`；核心包 `-p src` / `-p vitro/jsonmbt/src` 皆可 |
| 7 | **`moon test` 失败只打 FAILED 行** | 断言实际值看不到 | 用 `fail(s)` dump（`01` §2）；`assert_eq` 失败不含值 |
| 8 | **注入与测试间要 sleep** | 同秒快速改写，增量编译复用旧产物 ⇒ 假绿 / 假红 | 注入循环里 `sleep ≥1.5s`（`01` §3） |
| 9 | **fmt 口径** | `moon fmt --check` 本机可能 exit 127（git diff 子进程问题），别把 127 读成"格式没问题" | 口径 = `moon fmt` 后看 `git status` / `git diff` |
| 10 | **Windows 路径 grep** | 盘符路径里的 `\` 让 grep 模式失配 | 模式用 `[/\]` 双兼容（AGENTS 纪律 8） |
| 11 | **MoonBit 字符串中 `\` 会吃掉紧随的 `\{` 插值**（静默不插值、整段按源码文本落盘） | 写 `"\\u{\\{expr}}"` 这类「字面反斜杠 + 花括号插值」得到的是源码字面而非求值——jsonmbt P1-2 根因（控制字符转义整段 `\u{\{other…}}` 落进产物） | 拆运行时拼接：`write_string("\\u{"); write_string(x); write_string("}")`——任何「转义前缀 + 插值 + 后缀」都三段写 |
| 12 | **编译面扫描不豁免 `.gitignore`** | `tmp/` 虽被 gitignore，带 `moon.pkg` 的子目录照样被全仓 check 编译（2026-10-09 注入未定义类型即红 + `_build` 留产物双证）；嵌套 module（自带 `moon.mod`/`moon.work`）才是唯一边界（陷阱 #46） | 判「moon 看不看某目录」只看包边界，与 gitignore 无关；复现现场清理后**连 `_build` 产物一起核**（`_build/**/tmp/<pkg>` 残留可证编译曾发生） |
| 13 | **子目录裸跑 `moon build` root 冒泡** | 无构建文件的子目录里构建的是「最近构建文件所在仓」——在 tmp/vitro-pilot（Vitro 克隆，仓根无构建文件）跑 `moon build` 实际构建 jsonmbt 全仓；exe 没更新、后续 BYTE-DIFF 全是旧 exe 假象（2026-10-08 事故机制，2026-10-09 复现定因，陷阱 #47） | 行为验证前确认 cwd=root；嵌套克隆仓里跑 moon 命令前先想 root 是谁；moon 失败退出码恒 127，判「命令不存在」前先看 stderr |
| 14 | **构建报「拒绝访问 (os error 5)」/`Permission denied`** | 产物文件被外部句柄持有（**共享读即可**）时写路径共享冲突——2026-10-07 旧归因「`.moon-lock` 被占」已证伪（锁文件被占时 moon 优雅阻塞；「打开」冲突报 32，「写」冲突才报 5，两文案同因）（陷阱 #48） | 瞬时句柄重试即愈；频发用 `--target-dir` 换产物目录——**真因是避开被持文件，不是绕开锁**；与 #2 区分：本条当场报错（挡路），#2 静默旧产物（骗人） |
| 15 | **tmp 探针目录带 `moon.pkg` 时 `moon fmt` 同样向上冒泡** | 无 `moon.mod` 的探针目录里跑 `moon fmt`，冒泡找到宿主仓 root，把**宿主仓源文件全部 fmt 规范化**（#13 root 冒泡的 fmt 变体；「探针目录勿带 moon.pkg」对 fmt/check/build 一体适用） | 误犯后 `git checkout -- <被改文件>` 恢复并以 numstat=0 复核；探针需要 fmt 时自建嵌套 module（moon.mod + moon.pkg）且确认 cwd=该 module |
| 16 | **core `String::replace` 只换第一处** | `replace_all` 才全量——从 Go/JS replace 语义外推行尾归一（CRLF→LF）只换首个 `\r\n`，幂等闸/fmt 影子/byte 榜三类消费点齐假红（多字节行的伪装下更隐蔽） | 归一化一律 `replace_all` 或自写循环；审「归一化实现」先探一次多出现输入的输出 |
| 17 | **autocrlf=true 的 checkout 上还原判据** | `git -c core.autocrlf=false diff --numstat` 把行尾抖动报成全文件假差异（恒假红）；`git status` 的 M 行大部分是 checkout 行尾抖动 | 收尾还原判据用**默认 filter** 的 `git diff --numstat`（=0 即零内容改动）；突变还原判 `git status`，不判 `git show` 的 diff（行尾伪差异） |
| 18 | **Git Bash 命令串含真实控制字节 / heredoc 吃 `\`** | 直接传含控制字节的命令串被工具层拒（null byte 错）；heredoc 的 `\u`/`\\` 被再处理——构造含转义/控制字符的 JSON 反复翻车 | 探针脚本一律 Write 落盘成 .py 再跑；JSON 构造用 `python -c "import json; json.dump(...)"`，控制字符用 `chr()` 拼 |
| 19 | **Windows CRLF 工作区下 python 整文件写回变 LF** | 跨行替换走 universal newline 可匹配、写回 `newline='\n'` 把**整文件**行尾改掉——突变循环以为改了三行实际全文件被改，还原靠手工 diff 全乱 | 突变循环一律 **cp 备份还原**（别手工反向替换）；还原后 numstat=0 验证 |
| 20 | **嵌套探针 module 最小形态与 `moon check ./path` 被吞** | 探针包的 `moon.pkg` 须 **0 字节**（写 `{}` 都报 build plan 错）；从宿主仓根 `moon check ./sub/path` 被根 moon.mod 吞成 no work to do（静默假绿） | 探针 module：`moon.mod` 仅 `name = "x"` + 0 字节 `moon.pkg`；moon 命令必须 cd 进该 module 为根再跑（#13 同源） |
| 21 | **moon fmt 多文件批跑缓存假存活** | 宽度矩阵多文件一次 fmt：部分文件实际未被处理（同档两轮结果翻转——82 宽一轮「存活」一轮展开），误判界 | fmt 真值扫描用**单文件逐档协议**：每档新文件名 + 写后 sleep ≥2s + fmt + 判该行是否原样存活（`01` §7）；结论自相矛盾 = 本坑签名 |
| 22 | **`UInt64::to_int64` deprecated 警告** | moon check 报 deprecated（要求 reinterpret_as_int64）——新代码用 to_int64 即新增 warning | 值域 ≤ Int64 max 时用 `reinterpret_as_int64()`（无损）；值域可能超界时才需显式判定 |
